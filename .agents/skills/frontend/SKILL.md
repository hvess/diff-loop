# Front end

The front end draws what the Rust core decides. It holds no domain rule
the core owns — anchoring, instructions, what changed — and asks for it
instead. Its own logic is presentation: rows, the file tree,
highlighting, find, what to send and when.

## Data from Rust

- **Types come from the bindings.** Anything crossing the Tauri boundary
  is a type in `app/src/bindings/`, generated by `cargo test` (ADR 0001
  §3). Never edit them; never declare a second copy of one.
- **Calls go through `api.ts`**, one typed wrapper per command. Argument
  keys are the command's parameters in camelCase; Tauri maps them to the
  snake_case Rust names.
- **Errors are shown through `describe`** (`api.ts`), which turns a
  `CommandError` into a title and a detail a person can act on. A new
  error variant gets its words there, written per the `ux` skill.

## State

- **One store**, `useStore` in `store.ts` (Zustand). Every change is an
  action there; components call actions, never `setState` with logic.
  Actions are typed as function properties, not methods (ADR 0008 §2).
- **Select narrowly.** A component selects the smallest value it renders
  (`useStore((s) => s.viewed.has(path))`), so an unrelated change does
  not re-render it.
- **Replace, do not mutate**, so selectors see a change: a new `Map`, a
  new array. The one exception is documented where it is made (`viewed`).
- **Async results check they still apply.** An answer for a repository,
  base or file that is no longer current is dropped (`stillOpen`,
  `sameBase`, a signature check).
- **Persisted state** is only what ADR 0001 §5 and ADR 0004 name.

## Cost

The big-o skill's rules hold here: per keystroke, per frame, per watch
event and per IPC call, nothing proportional to a whole diff.

- **Long lists are virtualized** with TanStack Virtual, with
  `getItemKey` set to a stable key, so measured heights follow the item.
- **A `FileDiff` is never mutated**, and a refresh carries unchanged ones
  over as the same object. Per-file work is cached in a `WeakMap` keyed
  by the `FileDiff` (`counts`, `boundsOf`), so it runs once
  per version and the cache empties itself.
- **Memoize per load**, not per render: `useMemo` on the review, not on
  derived arrays rebuilt each time. The React Compiler memoizes
  components and hooks besides (ADR 0011 §2); a `useMemo` stays where it
  names the cost it bounds.
- **Tokenizing runs in a worker** (`highlight.worker.ts`, ADR 0011 §1):
  the UI thread only collects lines and places tokens.
- **Work a key starts that can wait is deferred**: `useDeferredValue`
  lets the selection show at once and the diff follow (`FilePane`).
- **Send what changed.** A refresh sends the signatures it holds (`known`)
  and gets back only what differs.

## Look and words

- **Colours, spacing and type come from the tokens** in `styles.css`
  through Tailwind classes; no raw colour in a component.
- **Every visible string follows the `ux` skill** (HIG `writing`):
  sentence case (menu items title case, HIG `menus`), plain words, errors that say what happened and what to
  do, meaning never in colour alone.

## Tests

- **Vitest, beside the module** as `<module>.test.ts` (ADR 0003). Test
  plain functions, and the store with `api` mocked (ADR 0004 §6).
  Components are checked by use: the `ux` skill's gate, and the UI judge.
- **A fix lands with the test that would have caught it**, as in Rust
  (quality-gate §8).

## Comments

The `comments` skill holds here unchanged: only what the code cannot say,
one line by default, anchors that resolve.

## Commands

Run in `app/`, all must pass:

```sh
npm run lint        # ESLint with types, no warnings (ADR 0006, 0008)
npm run typecheck   # tsc --noEmit
npm test            # Vitest
npm run build       # what ships
```
